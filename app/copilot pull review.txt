observeHeartRefillCountdown() runs an unbounded while (true) loop that wakes up every second. Because the ViewModel itself is always collecting currentUserProgress, this polling will keep running even when no UI is observing the countdown, which can hurt battery/CPU and trigger unnecessary recompositions. Consider deriving heartRefillCountdownText as a Flow that’s only active while subscribed (e.g., stateIn(WhileSubscribed) from a ticker flow), or otherwise stop the loop when the countdown isn’t needed/visible.

When remaining.isZero, this loop will call userRepository.refillHearts(userId) every second until currentUserProgress emits an updated value and cancels the collector. That can cause repeated DB writes / Firestore sync attempts depending on implementation timing. Consider calling refillHearts once and then breaking/suspending until progress changes (or at least gating with a local flag so it can’t be triggered repeatedly for the same refill moment)
